## Design Context

### Users

FIO WebUI is for storage engineers, SREs, system administrators, and performance engineers working directly with local disks, filesystems, and block devices. They need to assemble repeatable fio workloads, understand exactly what will run, monitor a live test without obscuring the data, and turn the captured evidence into a report. The interface is used in a high-consequence operational context, so clarity, traceability, and explicit destructive-write cues matter more than novelty.

### Brand Personality

Precise, composed, and industrial. The product should feel like a dependable instrument panel: quiet while idle, unambiguous while running, and direct when a configuration can damage data. Copy is concise and technical without being cryptic.

### Aesthetic Direction

A light-first operational workspace inspired by pipeline editors such as n8n and by modular construction systems. Use graphite-tinted neutral surfaces, crisp dividers, restrained green for healthy live data, amber for write risk and attention, and red only for destructive or failed states. Nodes should feel like compact equipment modules connected on a ruled work surface, not playful toy cards. Avoid marketing composition, neon-on-dark styling, decorative gradients, oversized typography, excessive rounding, glass effects, and card-heavy dashboards. Support dark mode only after the light workspace and data contrast are correct.

### Design Principles

1. Make execution semantics visible: stage order, parallel groups, barriers, targets, and inherited parameters must be scannable before a run starts.
2. Keep the primary loop continuous: build, validate, run, monitor, and report should feel like one workflow rather than separate products.
3. Reveal complexity progressively: nodes show operational summaries; the inspector carries detailed fio parameters and advanced overrides.
4. Treat metrics as evidence: always show units, source, capture state, and enough provenance to explain a report later.
5. Design for safe repetition: preserve drafts, make validation explicit, distinguish read and write risk, and keep high-frequency actions keyboard and touch accessible.
